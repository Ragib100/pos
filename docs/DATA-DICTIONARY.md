# POS System: Data Dictionary (v0.1 draft)

Companion to `ER-DIAGRAM.md`. For each of the **72 tables** it explains **why the table exists** and describes **every column**.

## How to read this document

- **Types** are logical (`uuid`, `text`, `numeric`, `int`, `bigint`, `boolean`, `date`, `timestamptz`, `jsonb`). Exact precision is in the conventions below.
- **PK** = primary key, **FK** = foreign key, **UK** = unique (usually together with `shop_id`).
- "(nullable)" means the column may be empty. Everything else is required.
- Every **shop-scoped** table has `shop_id` and is protected by Row-Level Security.
- Mutable tables also carry `created_at` and `updated_at` (`timestamptz`). They are listed only where they matter, to keep the tables short.

### Conventions

| Topic | Rule |
|---|---|
| IDs | `uuid` (UUIDv7). Generated by the server. |
| Money | `numeric(14,2)` |
| Quantity | `numeric(14,3)` (allows 1.25 kg) |
| Percent | `numeric(7,4)` |
| Time | `timestamptz`, stored in UTC |
| Soft delete | Master data uses `status`, never hard-deleted once referenced |
| Ledgers | Stock, customer and supplier balances are append-only ledgers; balance columns on parents are caches |

# 1. Tenancy, users and access

## 1.1 `users`
**Why:** One global login identity per person. A person who owns or works in several shops has a single account, and shop access is granted separately through `memberships`. Global (not shop-scoped).

| Column | Type | Description |
|---|---|---|
| id | uuid PK | User identifier |
| full_name | text | Person's name |
| phone | text UK | Mobile number, main login identifier |
| email | text UK | Optional email for login and recovery (nullable) |
| password_hash | text | Hashed password (never plain text) |
| is_platform_admin | boolean | True for system super admins who manage all shops |
| failed_login_count | int | Wrong-password counter for lockout |
| locked_until | timestamptz | Account locked until this time (nullable) |
| status | text | `active` or `disabled` |
| created_at | timestamptz | Account creation time |

## 1.2 `shop_types`
**Why:** Presets for pharmacy, grocery, clothing and so on. Choosing a type when creating a shop seeds sensible defaults, so adding a new shop type needs data, not code. Global.

| Column | Type | Description |
|---|---|---|
| id | uuid PK | Shop type identifier |
| code | text UK | Short code, e.g. `pharmacy`, `grocery`, `clothing`, `generic` |
| name | text | Display name |
| default_modules | jsonb | Feature flags turned on by default (batch/expiry, variants, weighted items) |
| default_attributes | jsonb | Starter custom product fields for this type |
| default_settings | jsonb | Starter tax, unit and receipt settings |

## 1.3 `shops`
**Why:** The **tenant**. Everything the business owns (products, customers, suppliers, sales) belongs to one shop. Holds the shop's identity, legal info and feature configuration.

| Column | Type | Description |
|---|---|---|
| id | uuid PK | Shop identifier (the tenant ID used in RLS) |
| shop_type_id | uuid FK | Which preset the shop was created from |
| name | text | Shop name |
| name_bn | text | Bangla shop name (nullable) |
| bin_number | text | VAT registration number (BIN) used on receipts and VAT reports (nullable) |
| phone | text | Shop's own contact number, printed on receipts (nullable) |
| email | text | Shop's own contact email (nullable) |
| currency_code | text | Currency, e.g. `BDT` |
| timezone | text | Shop's time zone for day boundaries and reports |
| default_language | text | `bn` or `en` for UI and receipts |
| enabled_modules | jsonb | Feature flags: batch_expiry, variants, weighted, combos, credit_sales, loyalty |
| settings | jsonb | Rounding, return days, stock policy, loyalty rule and similar rules |
| status | text | `active` or `suspended` |
| created_at | timestamptz | Creation time |

## 1.4 `branches`
**Why:** Physical locations of a shop. Stock, registers, shifts and sales happen per branch, while the catalog stays shared across them.

| Column | Type | Description |
|---|---|---|
| id | uuid PK | Branch identifier |
| shop_id | uuid FK | Owning shop |
| code | text | Short branch code, unique within the shop |
| name | text | Branch name |
| address | text | Address printed on receipts (nullable) |
| phone | text | Branch contact number (nullable) |
| bin_number | text | Branch-specific BIN if different from the shop (nullable) |
| status | text | `active` or `inactive` |

## 1.5 `registers`
**Why:** A POS terminal in a branch. Each has one cash drawer, so cash accountability and bill numbering work per register, and PIN login can be limited to known devices.

| Column | Type | Description |
|---|---|---|
| id | uuid PK | Register identifier |
| shop_id | uuid FK | Owning shop |
| branch_id | uuid FK | Branch where the terminal sits |
| name | text | Friendly name, e.g. "Counter 1" |
| device_identifier | text UK | Unique ID of the registered device (checked at PIN login) |
| status | text | `active` or `inactive` |

## 1.6 `roles`
**Why:** Named permission sets per shop (owner, manager, cashier, stock keeper). Each shop can customize its own roles.

| Column | Type | Description |
|---|---|---|
| id | uuid PK | Role identifier |
| shop_id | uuid FK | Shop that owns the role |
| name | text | Role name |
| is_owner | boolean | True for the full-control owner role |
| is_system | boolean | Seeded default role that cannot be deleted |
| max_discount_percent | numeric | Highest manual discount this role may give without approval |

## 1.7 `permissions`
**Why:** The fixed list of actions the system can control (create sale, change price, void bill). Roles are built from these. Global.

| Column | Type | Description |
|---|---|---|
| id | uuid PK | Permission identifier |
| code | text UK | Machine name, e.g. `sale.create`, `product.price.update` |
| description | text | Human-readable explanation |

## 1.8 `role_permissions`
**Why:** Joins roles to the permissions they grant (many-to-many), and marks which actions need a manager override.

| Column | Type | Description |
|---|---|---|
| role_id | uuid PK, FK | The role |
| permission_id | uuid PK, FK | The permission granted |
| requires_approval | boolean | If true, the action needs a manager PIN even for this role |

## 1.9 `memberships`
**Why:** The link between a user and a shop. It makes it possible for one user to belong to many shops, for a shop to have many owners, and for a cashier to work across shops, each with its own role.

| Column | Type | Description |
|---|---|---|
| id | uuid PK | Membership identifier |
| shop_id | uuid FK | The shop |
| user_id | uuid FK | The user (one membership per user per shop) |
| role_id | uuid FK | Role of this user in this shop |
| all_branches | boolean | True = can access every branch of the shop |
| pin_hash | text | Hashed 4-6 digit quick-login PIN, specific to this shop (nullable) |
| failed_pin_count | int | Wrong-PIN counter for lockout |
| pin_locked_until | timestamptz | PIN locked until this time (nullable) |
| status | text | `active`, `suspended` or `removed` |
| joined_at | timestamptz | When the user joined the shop |

## 1.10 `membership_branches`
**Why:** Restricts a membership to specific branches when `all_branches` is false (for example, a cashier allowed only at Branch 2).

| Column | Type | Description |
|---|---|---|
| membership_id | uuid PK, FK | The membership |
| branch_id | uuid PK, FK | A branch this member may access |
| shop_id | uuid FK | Shop (kept on the row so RLS applies) |

## 1.11 `auth_sessions`
**Why:** The server-side login session used for API authentication. It carries the **chosen working context** (shop, branch, register), so the server reads the tenant from here instead of trusting the client, and a session can be revoked immediately. Global table, looked up by token hash.

| Column | Type | Description |
|---|---|---|
| id | uuid PK | Session identifier |
| user_id | uuid FK | Logged-in user |
| membership_id | uuid FK | Shop membership the session acts as (nullable until a shop context is chosen) |
| branch_id | uuid FK | Branch selected (nullable until chosen) |
| register_id | uuid FK | Register in use (nullable until chosen) |
| token_hash | text UK | SHA-256 hash of the opaque session token (the token itself is never stored) |
| last_seen_at | timestamptz | Last request time |
| ip_address | text | Client IP at login (nullable) |
| user_agent | text | Client device/browser (nullable) |
| expires_at | timestamptz | Session expiry |
| revoked_at | timestamptz | When the session was revoked (nullable) |
| created_at | timestamptz | Session start |

**Why:** Organizes products into a browsable tree for the POS screen and for reports.

|---|---|---|

| shop_id | uuid FK | Owning shop |

| name | text | Category name |
| name_bn | text | Bangla name (nullable) |
| sort_order | int | Display order |

## 2.2 `brands`
**Why:** Optional manufacturer/brand label for filtering and reports.

| Column | Type | Description |
|---|---|---|
| id | uuid PK | Brand identifier |
| shop_id | uuid FK | Owning shop |
| name | text | Brand name |

## 2.3 `units`
**Why:** Units of measure (pcs, kg, litre, carton) per shop, and whether a unit allows decimals, which is needed for weight-based selling.

| Column | Type | Description |
|---|---|---|
| id | uuid PK | Unit identifier |
| shop_id | uuid FK | Owning shop |
| code | text | Short code such as `pcs`, `kg` |

## 2.4 `tax_rates`
**Why:** VAT/tax definitions so tax is calculated consistently and VAT reports are accurate.

| Column | Type | Description |
|---|---|---|
| id | uuid PK | Tax rate identifier |
| shop_id | uuid FK | Owning shop |
| name | text | Label, e.g. "VAT 15%" |
| rate_percent | numeric | Tax percentage |
| is_inclusive | boolean | True if prices already include this tax |
| status | text | `active` or `inactive` |

## 2.5 `attribute_definitions`
**Why:** Lets each shop define its own extra product fields (generic name for medicine, fabric for clothing) **without changing the database**. This is what keeps the backend common for all shop types.

| Column | Type | Description |
|---|---|---|
| id | uuid PK | Definition identifier |
| shop_id | uuid FK | Owning shop |
| key | text | Machine key stored in `products.attributes` |
| label | text | Field label shown in the UI |
| label_bn | text | Bangla label (nullable) |
| data_type | text | `text`, `number`, `date`, `bool` or `select` |
| is_required | boolean | Must be filled when creating a product |
| options | jsonb | Allowed choices for `select` fields (nullable) |
| is_searchable | boolean | Include in product search |
| sort_order | int | Display order in the form |

## 2.6 `products`
**Why:** The product master: what the shop sells, with its stock and tracking behavior. Product-level flags let one shop mix tracked and untracked items.

| Column | Type | Description |
|---|---|---|
| id | uuid PK | Product identifier |
| shop_id | uuid FK | Owning shop |
| category_id | uuid FK | Category (nullable) |
| brand_id | uuid FK | Brand (nullable) |
| base_unit_id | uuid FK | Unit in which stock is counted |
| tax_rate_id | uuid FK | Default tax rate (nullable) |
| name | text | Product name |
| name_bn | text | Bangla name for receipts (nullable) |
| description | text | Free-text description (nullable) |
| product_type | text | `simple`, `variable`, `combo` or `service` |
| is_weighted | boolean | Sold by weight at the counter |
| track_stock | boolean | Whether stock quantity is tracked |
| track_batches | boolean | Whether batch numbers are tracked (pharmacy, food) |
| has_expiry | boolean | Whether items carry expiry dates |
| allow_negative_stock | boolean | Allow selling below zero stock |
| attributes | jsonb | Values for the shop's `attribute_definitions` |
| image_url | text | Product image (nullable) |
| status | text | `active` or `inactive` |
| created_at | timestamptz | Creation time |

## 2.7 `product_variants`
**Why:** The actual **sellable and stockable unit** (size/colour, pack, or the single default variant of a simple product). Sales, stock and prices all point here, which keeps the model uniform for all shop types.

| Column | Type | Description |
|---|---|---|
| id | uuid PK | Variant identifier |
| shop_id | uuid FK | Owning shop |
| product_id | uuid FK | Parent product |
| sku | text | Stock code, unique within the shop |
| name | text | Variant label, e.g. "Red / XL" (nullable for simple products) |
| option_values | jsonb | Option choices such as size and colour (nullable) |
| cost_price | numeric | Default purchase cost |
| sale_price | numeric | Default selling price |
| is_default | boolean | True for the auto-created variant of a simple product |
| status | text | `active` or `inactive` |

## 2.8 `variant_barcodes`
**Why:** A variant can have several barcodes (manufacturer, shop-printed, carton). Scanning must resolve any of them to one variant.

| Column | Type | Description |
|---|---|---|
| id | uuid PK | Row identifier |
| shop_id | uuid FK | Owning shop |
| variant_id | uuid FK | Variant this barcode identifies |
| barcode | text | Barcode value, unique within the shop |
| unit_id | uuid FK | Unit the barcode represents, e.g. carton barcode (nullable) |

## 2.9 `unit_conversions`
**Why:** Sell or buy in different units of the same item (1 carton = 24 pieces) with optional pack pricing.

| Column | Type | Description |
|---|---|---|
| id | uuid PK | Row identifier |
| shop_id | uuid FK | Owning shop |
| variant_id | uuid FK | Variant being converted |
| unit_id | uuid FK | Alternate unit (e.g. carton) |
| factor_to_base | numeric | How many base units in one of this unit |
| sale_price | numeric | Special price for this pack size (nullable) |

## 2.10 `combo_items`
**Why:** Defines bundles ("meal deal", gift pack). Selling the combo deducts stock of each component.

| Column | Type | Description |
|---|---|---|
| id | uuid PK | Row identifier |
| shop_id | uuid FK | Owning shop |
| combo_variant_id | uuid FK | The combo being sold |
| component_variant_id | uuid FK | A variant inside the combo |
| quantity | numeric | Quantity of the component in one combo |

## 2.11 `branch_variants`
**Why:** Branch-level settings for a variant: price override, reorder threshold and whether it is sold there. Keeps the catalog shared while allowing branch differences.

| Column | Type | Description |
|---|---|---|
| id | uuid PK | Row identifier |
| shop_id | uuid FK | Owning shop |
| branch_id | uuid FK | The branch |
| variant_id | uuid FK | The variant |
| sale_price | numeric | Branch price override (nullable = use default) |
| min_stock | numeric | Low-stock alert threshold for this branch |
| is_active | boolean | Whether the variant is sold at this branch |

# 3. Inventory

## 3.1 `stock_batches`
**Why:** Tracks batch number and expiry date for items that need them (medicine, food). Enables expiry alerts and first-expiring-first-out selling.

| Column | Type | Description |
|---|---|---|
| id | uuid PK | Batch identifier |
| shop_id | uuid FK | Owning shop |
| variant_id | uuid FK | Variant this batch belongs to |
| batch_no | text | Batch/lot number, unique per shop and variant |
| expiry_date | date | Expiry date (nullable) |
| manufactured_date | date | Manufacturing date (nullable) |
| cost_price | numeric | Purchase cost of this batch |

## 3.2 `stock_levels`
**Why:** Fast "how many do we have now" lookup per branch (and batch). It is a cache of the movement ledger, updated in the same transaction as each movement.

| Column | Type | Description |
|---|---|---|
| id | uuid PK | Row identifier |
| shop_id | uuid FK | Owning shop |
| branch_id | uuid FK | Branch holding the stock |
| variant_id | uuid FK | Variant |
| batch_id | uuid FK | Batch (nullable for non-batch items) |
| quantity_on_hand | numeric | Current quantity |
| avg_cost | numeric | Weighted-average cost for valuation |

## 3.3 `stock_movements`
**Why:** The **append-only ledger** of every stock change. It is the source of truth: it explains any quantity, supports audits and lets `stock_levels` be rebuilt.

| Column | Type | Description |
|---|---|---|
| id | uuid PK | Movement identifier |
| shop_id | uuid FK | Owning shop |
| branch_id | uuid FK | Branch affected |
| variant_id | uuid FK | Variant moved |
| batch_id | uuid FK | Batch (nullable) |
| movement_type | text | `sale`, `return`, `purchase`, `purchase_return`, `adjustment`, `transfer_out`, `transfer_in`, `count_correction`, `opening` |
| quantity_delta | numeric | Signed change (negative = stock out) |
| unit_cost | numeric | Cost per unit at the time |
| reference_type | text | Source document type, e.g. `sale`, `goods_receipt` |
| reference_id | uuid | Source document ID |
| created_by | uuid FK | User who caused the movement |
| created_at | timestamptz | When it happened |

## 3.4 `stock_adjustment_reasons`
**Why:** Standard reasons for manual stock corrections (damaged, lost, stolen, expired) so loss reports are meaningful.

| Column | Type | Description |
|---|---|---|
| id | uuid PK | Reason identifier |
| shop_id | uuid FK | Owning shop |
| name | text | Reason label |
| name_bn | text | Bangla label (nullable) |

# 4. Sales, payments and returns

## 4.1 `sales`
**Why:** The core transaction: one row per bill (including held bills). Stores totals and links to the cashier, shift, register, branch and customer for reporting and audit.

| Column | Type | Description |
|---|---|---|
| id | uuid PK | Sale identifier |
| shop_id | uuid FK | Owning shop |
| branch_id | uuid FK | Branch where sold |
| register_id | uuid FK | Register used |
| shift_id | uuid FK | Shift during which it was sold |
| cashier_id | uuid FK | User who made the sale |
| customer_id | uuid FK | Customer (nullable for walk-in) |
| bill_no | text | Printed bill number, unique per shop and branch |
| client_request_id | text | Idempotency key sent by the client, unique within the shop. Prevents duplicate submissions on retry |
| status | text | `held`, `completed`, `voided`, `partially_returned`, `returned` |
| subtotal | numeric | Sum of line totals before bill-level discount |
| discount_total | numeric | Total discount given |
| tax_total | numeric | Total VAT, rounded once per bill to a whole taka (D-026) |
| service_charge | numeric | Service charge, if any |
| rounding_adjustment | numeric | Rounding applied to the total |
| grand_total | numeric | Final amount payable |
| paid_total | numeric | Amount received |
| change_given | numeric | Cash change returned |
| due_amount | numeric | Unpaid amount on credit sales |
| coupon_id | uuid FK | Coupon used (nullable) |
| print_count | int | Times receipt printed (reprints marked as duplicate) |
| note | text | Cashier note (nullable) |
| sold_at | timestamptz | Sale time |
| voided_by | uuid FK | User who voided it (nullable) |
| void_reason | text | Reason for void (nullable) |

## 4.2 `sale_items`
**Why:** Line items of a sale. Name, price, cost and tax are **copied at sale time** so history never changes when the catalog does, and profit can be computed.

| Column | Type | Description |
|---|---|---|
| id | uuid PK | Line identifier |
| shop_id | uuid FK | Owning shop |
| sale_id | uuid FK | Parent sale |
| variant_id | uuid FK | Variant sold |
| batch_id | uuid FK | Batch sold from (nullable) |
| name_snapshot | text | Product name at time of sale |
| name_bn_snapshot | text | Bangla name at time of sale (nullable) |
| sku_snapshot | text | SKU at time of sale |
| unit_id | uuid FK | Unit sold in |
| quantity | numeric | Quantity sold |
| unit_price | numeric | Price per unit charged |
| cost_snapshot | numeric | Cost per unit at that time (for profit) |
| discount_amount | numeric | Discount on this line |
| tax_rate_percent | numeric | Tax rate applied |
| tax_amount | numeric | VAT on this line, kept to two decimals (rounding happens once on the bill) |

## 4.3 `sale_promotions`
**Why:** Records which offers were applied to a sale or line and how much they took off, for promotion reports and audit.

| Column | Type | Description |
|---|---|---|
| id | uuid PK | Row identifier |

| sale_item_id | uuid FK | Specific line (nullable if bill-level) |
| promotion_id | uuid FK | The offer applied |

## 4.4 `payment_methods`
**Why:** The payment options a shop accepts (cash, card, bKash, Nagad, credit, gift card). Configurable per shop.

| Column | Type | Description |
|---|---|---|
| id | uuid PK | Method identifier |
| shop_id | uuid FK | Owning shop |

## Summary

- **72 tables:** 5 global (`users`, `permissions`, `shop_types`, `shops`, `auth_sessions`) and 67 shop-scoped with RLS.
- **Ledger tables** (never edited, only appended): `stock_movements`, `customer_ledger`, `supplier_ledger`, `loyalty_transactions`, `gift_card_transactions`, `audit_logs`.
- **Cached balances** (rebuildable from ledgers): `stock_levels.quantity_on_hand`, `customers.due_balance / store_credit_balance / loyalty_points`, `suppliers.payable_balance`.
- **Immutable after completion:** `sales` and its items, `shifts` and `z_reports` once closed.
